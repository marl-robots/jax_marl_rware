welford standardised is
performs a streaming update of mean and variance according to the Wolford algorithm 
and returns the normalized rewards (z-score) relative to the history so far.

welford, rstd = _welford_standardise(welford_prev, rewards)
def welford():
wmean = prev_wmean +((rewards - prev_wmean) / (sumw_prev + 1.0))
m2 = prev_m2 + (rewards - prev_wmean) * ((rewards - prev_wmean) / (sumw_prev + 1.0)) * prev_sumw
sumw = prev_sumw + 1.0
n = prev_n + 1.0
var = (m2 * n) / ((prev_sumw + 1.0) * (prev_n) + 1e-12)
std = (rewards - wmean) / (jnp.sqrt(var) + 1e-6)
rstd = rewards if n=1 else std



Receives an aggregate state (sumw, wmean, m2, n) in the form float32[E,N] 
and a new rewards in the form [E,N].

Updates the weighted mean (wmean) and 
m2 (the sum of the squared deviations needed to calculate the variance) 
in an online update with a weight of 1.

Calculates the variance/standard deviation of the aggregate and calculates the z-score:
std = (rewards - wmean) / (jnp.sqrt(var) + 1e-6)

If this is the first step (n <= 1) returns the raw rewards instead of normalizing it.

Returns the updated state (sumw, wmean, m2, n) and the processed rewards.

Why it's good
Provides real-time rewards normalization without storing a full history.

Improves stability in training by uniformly scaling rewards; includes a small addition to the standard deviation to prevent division by zero.

        Entropy = the measure of policy uncertainty for each agent at each step.
        Per-agent policy entropy - Entropy of each agent about its policy (at a given state/step). Measures local exploration.
        High entropy value = more random/exploratory policy; 
        low value = more deterministic/exploitative(greedy) policy. 
        Changing entropy_coef regulates the balance between exploration and exploitation.
        Decreasing entropy can indicate conflicts, agent dominance, or overfitting.
        Diversity/Coordination Index: Checks whether agents choose actions that are too diverse or coordinated.
        
        value loss
        Error measure in regression of the value:(sigma)sum((R-V)^2)
        High value loss = Critic is not suitable for returns(large errors), 
        which causes a shaky advantage and bad gradients for the policy. 
        affects training stability.
        Reasons: errors in calculating returns, unstable bootstrapping, or slow learning of 
        the criticality.
        Low value loss = The criticality predicts returns well; will contribute to stability in training.
        
        actor loss
        Measures how much policy should change according to the advantage: -(sigma)sum(log*pie(a|s)*A).
        High actor loss (especially without entropy) = Policy does not properly exploit benefits; 
        low entropy can indicate early convergence.
        Low actor loss = The policy chooses more actions with a positive benefit (more deliveries);
        not necessarily good if caused at the expense of exploration (entropy check).
        
        The total loss
        loss=actor_loss+value_loss_coef(lamda)*value_loss: measures what the optimizer is trying to minimize.
        A combination of the policy mismatch to the benefits (actor) 
        and the critic's inaccuracy (value). High value = problem/mismatch;
        low value = better match according to the defined criteria.

        Short practical recommendations
        If value_loss is high → improve crit: more crit updates, different learning rate,
        or target/value normalization.

        If actor_loss is high and entropy is high → policy is still exploring;
        you can wait or gradually reduce entropy_coef.

        If actor_loss is high and entropy is low → real problem in policy;
        check advantage/observations/architecture.

        Summary: High loss indicates problems in policy or critic (or both);
        decomposing loss into components and per-agent/time analysis is the way
        to diagnose and fix.
